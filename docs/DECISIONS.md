# DECISIONS

Implementation decisions made where the spec leaves a noncritical choice open (CLAUDE.md → Clarification). Append-only. Reference the decision ID in commits when relevant.

| ID | Date | Decision | Why |
|---|---|---|---|
| D-001 | 2026-09-02 | Repository line endings are LF, enforced by `.gitattributes` (`* text=auto eol=lf`). | The dev machine has `core.autocrlf=true` globally; Cloudflare, CI and Linux tooling expect LF. Prevents CRLF noise in diffs. |
| D-002 | 2026-09-02 | `docs/reference/BLOOMLAB_TECHNICAL_ARCHITECTURE_v1.md` is preserved verbatim as an input reference. The root `TECH_ARCHITECTURE.md` is the normative working architecture document derived from it plus the master spec. | Spec §102 requires `TECH_ARCHITECTURE.md` at root; the v1 reference was supplied under `docs/reference/`. Keeping both avoids rewriting the source. |
| D-003 | 2026-09-02 | Where the master spec and the v1 architecture reference differ in granularity, the master spec governs. The v1 "Initial Build Order" (TA§86, 40 steps) is used as intra-phase ordering guidance inside the master spec's 27 phases (§163). | Master spec §0 declares itself authoritative. |
| D-004 | 2026-09-02 | Requirement IDs use `PREFIX-NNN` (three digits, zero-padded). DELIVER-territory requirements (proposal, onboarding, handoff, retention) are filed under `SAL` because §125 defines no `DEL` prefix. | Stable, sortable, and stays within the spec's prefix list. |
| D-005 | 2026-09-02 | Phase 0 includes a dependency-free Node script `scripts/validate-requirements.mjs` that checks the requirements matrix and cross-document ID references. | Gives Phase 0 a real validation step and protects the control documents from drift before code exists. |
| D-006 | 2026-09-02 | The simulator event catalogue includes `EMAIL_OPENED` (present in TA§21, absent from master §44). | TA§21 is a superset; including it costs nothing and supports deliverability and analytics curriculum. |
| D-007 | 2026-09-02 | Package manager for Phase 1 is deferred to Phase 1. Node 22.18 and npm 10.9.3 are present; pnpm is not installed. | Not a Phase 0 concern; recorded so Phase 1 does not re-discover it. |
| D-008 | 2026-09-02 | TypeScript is pinned to `~6.0.3`, not 7.x. | `typescript-eslint` 8.69 supports TypeScript `<6.1.0`; the native TS 7 compiler is not yet supported by the lint toolchain. Revisit when typescript-eslint adds 7.x support. |
| D-009 | 2026-09-02 | npm workspaces (`apps/*`, `packages/*`, `worker`) are the monorepo tool; workspace packages are consumed as TypeScript source via `exports` (no build step per package). | npm 10 is already present, needs no global install, and Vite/Vitest/Wrangler all resolve linked TS sources directly. Resolves D-007. |
| D-010 | 2026-09-02 | React Router 8 in declarative mode (single `react-router` package). Routes live in a registry (`apps/web/src/app/routes.tsx`) where every screen is a `React.lazy` chunk and a route may be gated by a feature flag. | Boring, well-documented routing; per-route chunks give PERF-001 its foundation; the registry is where INF-010 flag gating happens in one place. |
| D-011 | 2026-09-02 | Fonts are self-hosted through `@fontsource` packages (Bricolage Grotesque Variable, Inter Variable, IBM Plex Mono 400/500). | Offline/PWA use (DATA-003) needs no runtime request to Google Fonts; matches DES-005 faces exactly. |
| D-012 | 2026-09-02 | The Wrangler config lives in `worker/wrangler.jsonc`; `apps/web/vite.config.ts` points the Cloudflare Vite plugin at it via `configPath`. `wrangler deploy` runs from `apps/web`, following the deploy redirect the plugin writes to `apps/web/.wrangler/deploy/config.json`. | Keeps the §102 layout (worker/ separate from apps/web) while using the documented Vite-plugin build → deploy flow. |
| D-013 | 2026-09-02 | Environment selection is build-time: `CLOUDFLARE_ENV` picks the Wrangler environment (Worker name + `BLOOMLAB_ENV` var) and Vite `--mode` (`development` → local, `preview` → preview, `production` → production) sets the client's environment. `/system` warns when the two disagree. | The Cloudflare Vite plugin applies environments at build time; `wrangler deploy --env` has no effect (Cloudflare docs). |
| D-014 | 2026-09-02 | A `/system` diagnostics screen (versions, environment, Worker health, flag table) exists behind the `system_diagnostics` flag, on in local/preview and off in production. | Gives Phase 1 a real flag-gated route (INF-010) and a genuine client ↔ Worker wire to verify, without inventing a product screen ahead of Phase 7. |
| D-015 | 2026-09-02 | Token CSS variables carry a category prefix: `--bl-color-*`, `--bl-space-*`, `--bl-radius-*`, `--bl-shadow-*`, `--bl-motion-*`, `--bl-font-*`, `--bl-holo-*`, `--bl-density-*`, `--bl-z-*`, `--bl-bp-*`. | Lets `tokens.test.ts` prove every TA§3 category exists and keeps the CSS/TS mirror verifiable. Supersedes the shorter names first proposed in DESIGN_SYSTEM.md. |
| D-016 | 2026-09-02 | `engines.node` is `>=22.22.0` (react-router 8 requirement). The dev machine runs 22.18 with npm engine warnings; CI resolves the latest 22.x via `.nvmrc`. | Honest floor for the dependency set; upgrading the local Node is recommended but not blocking. |
| D-017 | 2026-09-02 | Contrast tuning within the spec palette family: Ink Faint `#8F8AA5` → `#86819C` (3.6:1 on Cloud, clears the large-text bar on every light surface; still not used for small text). New role tokens `--bl-color-link` / `--bl-color-focus` = `#3B69BD` (Info darkened; 5.1:1 on Cloud) because Info `#5D90D9` reaches only 3.1:1 as text. Inside ink surfaces links and focus use Aqua (11:1). Success/Warning are never used as text. | Spec §65 allows tuning "for contrast and final polish, while retaining the Doodlemon-inspired family"; `contrast.test.ts` enforces the pairings (A11Y-004). |
| D-018 | 2026-09-02 | `HoloMaterial` renders as `div` or `span` (never a button); interactive semantic components (SkillCard, HoloTerritory, ClientCaseCover) wrap it in their own `<button>` and use only phrasing content inside. | Keeps the HTML valid (no flow content inside buttons), keeps one focus ring on the real control, and avoids polymorphic prop typing. |
| D-019 | 2026-09-02 | A `/design` gallery route behind the `design_gallery` flag (local/preview only) shows every primitive and semantic component in every state. | Phase 2 requires visual verification at five widths; the gallery is the fixture for that and for the screen-coverage review, without inventing product screens ahead of Phase 7. |
| D-020 | 2026-09-02 | Preview deployments use one shared Worker, `bloomlab-preview`, redeployed by CI for every pull request (build with `CLOUDFLARE_ENV=preview` + Vite mode `preview`). Production deploys the `bloomlab` Worker on every push to `main`. Both jobs are gated on the repository variable `CLOUDFLARE_DEPLOY` and the `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` secrets. | TA§76 asks for previews inspectable on a phone before merging; a single preview Worker satisfies that for a one-person project without per-PR isolation. Per-PR preview URLs can be added later with `wrangler versions upload` if concurrent branches ever need them. |
| D-021 | 2026-09-02 | `HoloMaterial` is modelled on the foil trading card in the Doodlemon puzzle view (a photographed holo card with a gentle float), not on the landing-page tiles (which only lift on hover). Bloomlab reproduces the foil optics in CSS — sweeping spectral bands, metallic grain, pointer-following glare, rim light, direction-aware shadow — and adds the pointer physics the spec asks for (≤ 6° tilt, 420 ms settle, touch press/drag/release). No idle float: spec §148/MOT-004 forbids constant holographic animation. | The reference's DOM has no pointer-driven layers; its "holo feel" is the foil photograph plus tactile hover. Reproducing the optics rather than the photo keeps Bloomlab's own identity (pastel palette, light ground) and stays deterministic and cheap (no blur filters, no per-pixel work). |
| D-022 | 2026-09-02 | HoloMaterial smoothing (follow and settle) is exponential easing in a `requestAnimationFrame` loop that writes seven custom properties and stops when the pose converges; the stylesheet has no transitions on the pointer-driven properties. | In the production bundle, CSS transitions on properties whose values come from `var()`-driven `calc()` never advanced (transform, band position, glare and shadow all stayed at their pre-hover values on the deployed preview while `transition: none` fixed them instantly); the dev server did not reproduce it. Easing in JS behaves identically in dev, in production and in tests, gives a spring-like feel, and costs a few multiplications per frame only while a card is moving. |
| D-023 | 2026-09-02 | From a live study of the reference (real pointer): its tiles lift 8 px with a deeper shadow and a pastel gradient ring on hover, its foil card is a photograph with a slow float, and the only pointer-driven motion is a background parallax. Bloomlab adopts the *tactile* half — the hover lift is 5 px and the shadow deepens with it, and the rim light is tinted with the palette so the edge reads as iridescent foil — and keeps its own procedural material and spec physics (tilt, glare, spectral shift, settle). No idle float, no parallax, no copied gradient values. | Spec §62 asks to match the reference's tactile, holographic *feeling* and forbids copying art or composition; §148 / MOT-004 forbid constant animation. The lift-and-shadow cue is what makes the reference's hover feel physical; the tinted rim answers "iridescence" without a photograph. |
| D-024 | 2026-09-02 | Visual acceptance reviews run through a small DevTools-Protocol driver (`scripts/review/`, `npm run review:capture` / `review:holo`) against a production build, with outputs in the git-ignored `.review/`; the in-app browser pane is used for spot checks only. | The pane only composites frames during input actions, cannot emulate reduced motion, and its captures time out or tile at fresh navigations, so eased motion looked broken and narrow widths could not be captured reliably. The driver gives exact viewports (touch emulation below 768 px), full-page captures, real mouse/touch events with a live frame loop and media emulation, and it works the same on CI-class machines. Playwright would do the same but adds a browser download and a dependency for a script that needs ~150 lines. |
