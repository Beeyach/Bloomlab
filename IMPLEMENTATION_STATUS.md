## CURRENT PHASE

Phase 10 — Simulator Core: **the shared deterministic engine exists and runs; no workflow executes yet, and that boundary is held everywhere.** `packages/simulator-core` is pure TypeScript importing nothing outside itself — a source-level test enforces the absence of React, the DOM, IndexedDB, Dexie, Cloudflare, `fetch`, Claude, `Math.random()`, `Date.now()` and any read of the machine's timezone. It models one simulated GoHighLevel account across twenty-one id-addressed collections plus the run's log, queue, execution records, clock and generator position, and transitions it with `State + Event + Configuration → New State + Generated Events + Execution Records`: pure reducers for all 26 catalogue events, never mutating the state handed to them, with generated events fed back through the same processing path as injected ones so there is no second route into the state. Every scenario owns its clock — a minute and an hour are absolute, a day is a calendar day that holds 09:00 across a daylight-saving change — and the Time Machine's four actions really move it and run what is due. The queue is totally ordered by (timestamp, insertion sequence, stable id), an unbounded same-instant cascade stops at 500 events with an explicit diagnostic rather than a silent drop, and the scenario — not the interface — decides what may be injected. Randomness is a seeded generator whose position survives a snapshot; runs are stored as scenario + append-only log + a checkpoint every 25 events; replay re-runs only root events and regenerates consequences, so it reproduces a run exactly without duplicating an id or touching the live one; rewind is replay to an earlier index; reset returns to the authored state without mutating the content. Saves ride the existing local-first sync path (`sim_projects`, `sim_events`, `sim_snapshots`), and a reload resumes a run at the same instant with the same history, queue and seed — offline included. A translation-only adapter turns real simulator output into Phase 9's `GradingContext` and is proved by grading state, event, timing and sequence assertions against a real run; it never claims an architecture, so no authored exercise becomes gradable and `EXERCISE_RUNTIMES` stays empty on purpose. The internal harness at `/system/simulator` (behind the diagnostics flag, never in production) drives all of it against the real engine. A reset starts a new **generation** of the run, so a reset run's append-only history can never ask for an id an earlier life used, and no history row is ever rewritten, resurrected or deleted (D-087). This phase also carried three global design corrections, all three now finished: eyebrows and monospace are banned product-wide (DES-021, DES-022), and **REAL TABLET USER CHECK: PASS** — the user tested diagnostic cards A to I on their actual tablet and reported all nine clean, with the Skill Map's holographic interaction clean on the same device, so the D-075 tablet issue is confirmed fixed. Getting there took a change of method: three fixes in a row had been chosen from desktop evidence against a symptom only a real device showed, so rather than a fourth guess this phase shipped the instrument that could name the cause — `/system/holo`, nine copies of the real interactive card with exactly one property changed each (D-086). Case A is the card as it ships, so the fix is one of the two WebKit version gaps closed alongside it, most likely `button { -webkit-appearance: none }`, without which WebKit before Safari 15.4 paints the native button chrome on `:active` as a square fill over the button's box. What the diagnostic settled is that the material was never at fault: every case that removed a piece of it came back identical, so nothing about the holographic interaction was weakened. The Skill Map's selected territory also lost its ink ring for a spectral edge, a soft lilac pool, a material that wakes up with it and the word "Showing" (D-088). Verified by 199 simulator-core tests, 19 adapter and persistence tests, 21 design-rule tests, 11 holographic material tests, the five-width capture audit, and Chrome probes covering the harness, keyboard, touch, offline, the reset-then-new-activity journey and the nine holographic diagnostic cases. Phase 10 is ready for final merge sign-off. Phase 11 has not been started.
