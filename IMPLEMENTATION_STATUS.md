## CURRENT PHASE

Phase 10 — Simulator Core: **the shared deterministic engine exists and runs; no workflow executes yet, and that boundary is held everywhere.** `packages/simulator-core` is pure TypeScript importing nothing outside itself — a source-level test enforces the absence of React, the DOM, IndexedDB, Dexie, Cloudflare, `fetch`, Claude, `Math.random()`, `Date.now()` and any read of the machine's timezone. It models one simulated GoHighLevel account across twenty-one id-addressed collections plus the run's log, queue, execution records, clock and generator position, and transitions it with `State + Event + Configuration → New State + Generated Events + Execution Records`: pure reducers for all 26 catalogue events, never mutating the state handed to them, with generated events fed back through the same processing path as injected ones so there is no second route into the state. Every scenario owns its clock — a minute and an hour are absolute, a day is a calendar day that holds 09:00 across a daylight-saving change — and the Time Machine's four actions really move it and run what is due. The queue is totally ordered by (timestamp, insertion sequence, stable id), an unbounded same-instant cascade stops at 500 events with an explicit diagnostic rather than a silent drop, and the scenario — not the interface — decides what may be injected. Randomness is a seeded generator whose position survives a snapshot; runs are stored as scenario + append-only log + a checkpoint every 25 events; replay re-runs only root events and regenerates consequences, so it reproduces a run exactly without duplicating an id or touching the live one; rewind is replay to an earlier index; reset returns to the authored state without mutating the content. Saves ride the existing local-first sync path (`sim_projects`, `sim_events`, `sim_snapshots`), and a reload resumes a run at the same instant with the same history, queue and seed — offline included. A translation-only adapter turns real simulator output into Phase 9's `GradingContext` and is proved by grading state, event, timing and sequence assertions against a real run; it never claims an architecture, so no authored exercise becomes gradable and `EXERCISE_RUNTIMES` stays empty on purpose. The internal harness at `/system/simulator` (behind the diagnostics flag, never in production) drives all of it against the real engine. A reset starts a new **generation** of the run, so a reset run's append-only history can never ask for an id an earlier life used, and no history row is ever rewritten, resurrected or deleted (D-087). This phase also carried three global design corrections, all three now finished: eyebrows and monospace are banned product-wide (DES-021, DES-022), and **REAL TABLET USER CHECK: PASS** — the user tested diagnostic cards A to I on their actual tablet and reported all nine clean, with the Skill Map's holographic interaction clean on the same device, so the D-075 tablet issue is confirmed fixed. Phase 17 — Pricing Arena: **a learner prices a deal on what the client asked for, not on what the deal costs, because what it costs is not on the screen until they have submitted.** PRICE IT is a deal desk with seven areas of one object: the client's own requirements, the scope lines that answer them, the price, the payment, the timeline, the recurring fee and the exclusions the learner writes. Everything the learner sees is their own arithmetic or their own promise. The total, what is due on signature and what is left on delivery are all built from the eight numbers they set; the hours behind each scope line, what an hour costs, the floor and the margin are not rendered anywhere until the attempt is in (EXR-016, D-162). Taking a line out says what it leaves the client with and, where it answers something the client asked for, says that nothing in the deal answers it any more, which is a fact about the promise rather than about the money (PRI-001). The pricing engine lives in `apps/web/src/exercise/pricing/` and is the only place a pricing figure is worked out: money is whole dollars rounded once at the boundary, margin divides by revenue rather than cost, and recurring revenue is deliberately kept out of the margin on a build so a retainer cannot make a thin quote look healthy (D-160). There is no target price. A quote is judged on whether it clears what the work costs, carries the contingency the scenario's own risk score asks for, holds the margin the business works to, and charges for the scope it promised: $2,200 and $3,200 both pass the same Summit deal, and taking the migration out lowers the floor so a smaller deal is defensible cheaper while the checks say which promise it stopped keeping. The hourly delivery cost is authored per exercise rather than invented in code, because nothing in the source establishes a universal rate (D-161). Auditing the seed exercise found its critical rule checking `price.total gte 1200` against a path nothing produced and a number nothing traced to; it is now `price.at_or_above_floor`, derived from the scenario's own 22 hours (D-163). `SC-glowhaus-two-locations` carries the scope training that walks all thirteen dimensions SAL-016 names, with an opening date twelve days out that makes rush a decision rather than a checkbox, and it grades deterministically end to end today.
