# Scope SaaS, white-label and Marketplace operations

## A distinct operating business

SaaS Mode packages access and billing around an agency offering. White-label settings change branding and distribution. A Marketplace app extends the platform under its own installation, permission and support contract. These are related possibilities, not interchangeable names for a reusable workflow.

Before choosing any of them, define the paying customer, support owner, account provisioning, cancellation, usage exposure and data exit. A polished logo cannot repair an unbounded support promise. A successful demonstration does not establish billing operations, security review or customer demand. This material is specialist-only and does not silently expand a Field Ready implementation into a software business.

## Verify three different boundaries

HighLevel's current Agency Sub-Account documentation places supported SaaS billing operations in the agency-owned workspace. Confirm the selected plan and configuration rather than teaching a permanent universal price. Desktop app branding and a branded web-login domain are separate configurations; changing one is not proof that both are ready.

The current Marketplace distribution model asks who uses an app, who may install it and whether agency bulk installation is supported. Those choices affect token scope and account access. A private pilot is not approval for public distribution. Read the current distribution and authentication contracts before promising an installation route.

## Permission changes have consequences

An agency can restrict visible apps to approved selections. Disapproving an installed app can uninstall it and remove capabilities its workflows depend on. Inventory consumers, coordinate change approval and verify recovery before changing a production app policy. Never include a live token in a snapshot or lesson answer.

The practical keeps three workstreams distinct and refuses an unsafe distribution decision. No subscription is created, branded app built or Marketplace installation performed. Real entitlement, consent, security and commercial validation remain external work. A local pass is evidence of the supplied decision contract, not permission to operate a live SaaS product.
