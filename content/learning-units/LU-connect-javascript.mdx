# Transform a payload defensively

## Explicit input and output

Operator JavaScript often selects fields, normalises a value, filters an array or chooses a branch. A utility should define its accepted input and returned output. Consider native configuration before assuming the maintenance burden of custom code.

input.active === true accepts only boolean true. A truthiness check also accepts the string "false". Array.isArray validates array shape before array methods. Number.isFinite checks numbers without coercing arbitrary text. Nullish fallback preserves zero and false; logical OR can discard them.

## Trace this utility

`function project(input) { return { active: input.active === true, budget: input.budget ?? null, tags: Array.isArray(input.tags) ? input.tags.filter(tag => typeof tag === "string") : [] }; }`

The function builds a new object without mutating input. A string "false" becomes active false, zero budget stays zero, missing budget becomes null, and tags retain only strings. Missing tags become an empty array. This is a teaching transform, not a complete production consent validator.

The faulty condition if (input.active) sendMessage() would send when active is "false". Repair the type contract and condition; retries or waits do not repair an incorrect business rule.

## Bound failure

Catch expected JSON parsing errors and return a clear failure, not a successful empty object. Distinguish rejected asynchronous work from HTTP error statuses. Test valid input, missing properties, wrong types, empty arrays, zero and false. Never evaluate a payload as executable code.

The practical asks you to trace outputs and choose the repaired condition. Bloomlab parses your JSON answers, not submitted JavaScript. It performs no code execution, terminal session or network request. General-purpose coding and live deployments remain outside this foundation.
